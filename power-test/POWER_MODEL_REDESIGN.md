# Power-model audit and replacement contract

## Decision

The frozen `power-test/fitted_surface.json` remains a diagnostic baseline. The
implemented v4 candidate has one four-coordinate dense law per hardware and a
separate MoE law. It is generated by `fit_clean_power_pipelines.py` and is not
yet sealed because genuinely new request-trace transfer data are pending and
the showcased rate-2 trace still fails temporal ACF despite improved amplitude.

The dense law does not route on model name, TP, or arrival rate. The MoE feature
law is shared, but its coefficients are calibrated separately for
GPT-OSS-20B and GPT-OSS-120B. This is an explicit support boundary: the legacy
data contain TP1/2 only for 20B and TP4/8 only for 120B, and the attempted joint
fit improved 120B by trading away 20B accuracy. It would be misleading to call
that joint fit architecture transfer. New MoE architectures remain unsupported
until the new transfer campaign is scored.

## What the audit found

The all-run audit scores 450 repetitions: 160 train, 80 in-domain development,
108 related-model twins, 48 rate-4 runs, 44 held-out-model runs, and 10 dtype
calibration runs. It covers seven models, A100 and H100, TP1--TP8, and rates
0.125--4 requests/s.

The paper draft and deployed dense artifact disagree:

| Contract | Paper draft | Executed dense artifact |
|---|---|---|
| design | 18 columns with phase duty and tokens/iteration | 4 fitted columns; exact phase work retained as diagnostics |
| power cap | unconditional 400/700 W per GPU | no cap unless telemetry binds one |
| TP/residence fit | TP link and resident terms described | both forced to zero with the idle anchor |
| MoE | separate five-term model | dense artifact still used as an unsupported comparator outside the MoE surface's narrow support |
| reported scope | split policy described | the original fit report scores only train and in-domain development |

The strongest numerical findings from supported dense runs are:

- median energy error is 6.50%, RMSE is 23.5 W/GPU, range NRMSE is 0.119,
  ACF R2 is 0.979, and KS agreement is only 0.392;
- A100 is worse than H100 on every aggregate error metric in this audit;
- Soft-DTW and range NRMSE have Spearman correlation 0.99, while energy error
  and ACF error correlate only 0.07. Energy and temporal fidelity are separate
  failure axes;
- arrival rate correlates 0.82 with ACF error. Busy fraction, decode batch, and
  waiting requests each correlate about 0.75--0.76 with ACF error, but they
  co-move with rate and are associations rather than identified causes;
- memory utilization and retrospective residual-step magnitude each correlate
  0.58 with per-GPU RMSE;
- the signed bias flips systematically with TP. A100 70B TP4 underpredicts by
  roughly 13--14%, while TP8 is close to zero or overpredicts. The pattern is
  shared by the Llama and DeepSeek twin models and also appears on H100.

The TP pattern is consistent with the current fitting code: when a loaded-idle
anchor is supplied, it fixes the idle coefficient and fits only columns 3 and
above. The TP-link and resident-footprint columns are therefore exactly zero.
This prevents the fit from representing configuration-dependent standing and
stall power even though those columns appear in the design.

## Replacement architecture

The request trace remains the input. The timing layer produces explicit engine
iterations before the power layer is evaluated:

```text
requests -> scheduler/KV state -> iterations -> wall-time work/stall duties
         -> equilibrium GPU power -> one-state device response -> meter kernel
```

For each iteration, the timing layer exposes:

- prefill and decode tokens, context/KV geometry, and batch;
- iterations per second and tokens per iteration;
- compute FLOPs and HBM bytes per GPU;
- collective count and bytes implied by TP and the declared topology;
- predicted compute/memory duty, exposed collective/synchronization stall
  duty, and idle duty.

The clean dense equilibrium map is a four-coordinate nonnegative regression
per hardware:

```text
P_eq,gpu = idle_h
         + footprint_h(busy * local_weight_fraction)
         + compute_h(compute_utilization)
         + memory_h(sqrt(busy * memory_utilization))
```

Compute utilization is the sum of exact GEMM and causal-attention FLOP rates;
memory utilization is exact iteration weight bytes plus attention bytes. These
work quantities are computed by the timing roofline and conserved onto the
250-ms ledger rather than reconstructed from token counts. The idle coefficient
is fixed from the settled portion of source-run idle gaps lasting at least four
seconds; the first two seconds of each gap are discarded. Busy gating prevents
checkpoint size from raising the hardware idle floor. Compute remains
uncompressed to preserve prefill spikes. The square root is the only concavity
assumption, and applying it as `sqrt(busy * memory_utilization)` preserves the
average active response during partially idle bins. No model name, TP
identifier, arrival rate, phase label, trace time, or hidden state enters the
dense regression.

The MoE map uses loaded idle, an optional multi-GPU link floor, lagged logical
memory utilization, duty-aware square-root exact compute utilization, engine
iterations per second, and log decode batch. The link floor is omitted when all
supported TPs exceed one because it then exactly aliases idle. Both maps apply
the measured H100 one-second trailing meter window and no learned hidden state.

## Fitting population and loss

- Fit per-GPU power on all 225 dense and 60 MoE source repetitions at rates
  through 2 requests/s. The repetitions replay nearly identical input lengths,
  order, and relative arrivals, so none is labeled independent development.
- First average the response-filtered design and measured target into matched
  nonoverlapping one-second bins without crossing run boundaries. Give equal
  total loss to each dense run and equal mass within the run to seconds below
  and above its power p90. This makes upper-tail prefill fidelity an
  explicit objective rather than allowing long decode intervals to dominate.
- Keep all 57 rate-4 runs out of fitting as retrospective stress tests and all
  108 related-model twins as transfer comparators. New request traces are the
  external validation gate.
- Report signed bias with absolute energy error. A sign flip must never be
  summarized as an improvement through absolute value alone.

## Support boundary

The dense artifact supports A100/H100, TP1--TP8, the recorded continuous-
batching policy and topology, 250 ms simulation bins, and the observed dense
architecture descriptor range. GPT-OSS-20B support is A100 TP1/2;
GPT-OSS-120B support is A100 TP4/8. It is conditional on known output lengths
for offline replay. Online use must supply an output-length distribution.

It does not support PP, EP, DP, CP, an unrecorded scheduler policy, a changed
power cap/P-state/application clock, or a different topology. Historical runs
without clock and engine-state telemetry cannot identify a power-state change;
the model must expose that as unsupported instead of fitting a run-time step.

## Acceptance evidence

Every frozen candidate is scored on energy error, soft-DTW, range NRMSE,
per-GPU RMSE, ACF R2/MAE, KS agreement, and signed bias for every rate and
every hardware/model/TP cell. Results are separated by split and support
status. No paper trace is selected until its cell-level metrics are visible in
the all-run report.

Dense source medians are 1.66% energy error, 13.47 W/GPU RMSE, 0.9933 ACF R2,
and 0.540 KS agreement. Dense twin comparators score 2.05%, 11.68 W/GPU,
0.9952, and 0.647. Dense rate-4 stress scores 2.71% energy error,
13.63 W/GPU RMSE, and 0.725 median ACF R2. The four showcased Llama-70B A100
TP4 runs now contain predicted upper-tail pulses instead of a median line, but
the rate-2 run remains temporally wrong (negative ACF R2). The model therefore
improves spike amplitude without claiming that exact loaded-scheduler timing is
solved.
